Building This Site With Claude Code

Notes on how this site actually got made — from a first conversation in Claude to a live, auto-deploying site — for anyone else figuring out Claude as they go.

StatusLive
ImpactMeta
ToolsClaude, Claude Code, GitHub, Netlify

I started in chat, not in code

Before writing anything, I talked the whole idea through with Claude — what the site should actually cover and who might read it. That turned into a homepage draft, built and rendered right in the conversation, that I could react to instead of designing from a blank page.

The scope grew as I went

The first draft stuck close to one topic: the marketing ops work. The more we talked, the more I wanted something that mixed that with the rest of my life — arts and crafts, mom life, learning Claude — tagged so people can find the part they care about. Each shift was just a conversation, not a rebuild from scratch.

Where design directions came from

When I wasn't sure about the visual style, Claude built a few real, working previews side by side instead of just describing options — that made picking one a lot easier than imagining it.

Handing off to Claude Code

Once the content and design direction felt right, I moved the working draft into Claude Code to build it out for real — proper file structure, project pages, and eventually deploying it. Claude Code doesn't share the earlier chat's memory, so the handoff worked best by bringing over a real starting project instead of a blank folder, plus a README spelling out the plan.

Getting it into git

First step was version control, so I'd stop being one bad edit away from losing work. Claude Code walked through it directly in the folder:

  • Ran git init and set a local git identity, since this machine had never committed anything before
  • Staged the real site files and made an initial commit with a plain-English message describing what was in it
  • Added a small .gitignore for OS junk files before anything else went in
Key decision

My project folder had an extra layer of nesting — a "portfolio-site" folder containing another "portfolio-site" folder, and the actual index.html lived in the inner one. Claude Code caught that the repo root needed to be wherever index.html actually sits, since that's what Netlify and GitHub Pages expect to find at the top level. Easy to miss, annoying to untangle later.

Pushing to GitHub and going live on Netlify

From there it was: create an empty repo on GitHub, add it as the remote, push. Then sign up for Netlify, connect the GitHub repo, and since this is a plain static site with no build step, leave the build command blank and point the publish directory at the repo root.

Where it stands now

The site is live at michellestunkard.netlify.app and redeploys automatically every time changes get pushed to the main branch on GitHub — no manual upload step, ever again. The update loop going forward is: describe the change, review a live preview, commit with a clear message, push, watch Netlify pick it up. Still ahead: a custom domain, and pulling the noindex tag off each page as its content stops being a placeholder.

What I'd tell someone starting out

  • Talk through the idea before you touch code — it's faster to redirect a conversation than to redo a build.
  • Get something rendered early, even rough. Reacting to a draft beats staring at a blank page.
  • Don't be afraid to change direction mid-way. Structure and tone are cheap to change until you've built a lot on top of them.
